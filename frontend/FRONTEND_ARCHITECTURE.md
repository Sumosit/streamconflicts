# Архитектура фронтенда «Стримархив»

## Назначение

Angular-приложение показывает каталог конфликтов стримеров и отдельные индексируемые страницы с хронологиями. Фронтенд отвечает за навигацию, представление материалов, поиск и фильтрацию. Источником истины для редакционных данных в дальнейшем должен стать API или CMS.

## Технологический стек

- Angular 20, standalone-компоненты.
- Angular Router для постоянных URL материалов.
- SCSS и глобальные CSS-токены.
- Signals для локального состояния интерфейса.

## Структура

```text
src/
├── app/
│   ├── app.ts                 # главная страница и состояние каталога
│   ├── app.html               # лента, поиск, фильтры и служебные блоки
│   ├── app.scss               # стили главной страницы
│   ├── app.routes.ts          # таблица маршрутов
│   └── conflict-page/
│       ├── conflict-page.ts   # выбор материала по slug
│       ├── conflict-page.html # страница конфликта и таймлайн
│       └── conflict-page.scss # стили страницы конфликта
├── styles.scss                # палитра, токены и глобальные правила
├── styles/
│   └── _ui-kit.scss           # переиспользуемые UI-примитивы
└── index.html                 # метаданные документа
```

## Маршруты

| Маршрут | Назначение |
|---|---|
| `/` | лента и архив конфликтов |
| `/conflicts/:slug` | отдельная страница конфликта |

`slug` является постоянным публичным идентификатором. После публикации его нельзя менять без HTTP-редиректа со старого адреса.

## Модель данных

Минимальная сущность конфликта:

```ts
interface Conflict {
  id: number;
  slug: string;
  title: string;
  summary: string;
  status: 'developing' | 'quiet' | 'closed';
  participants: Participant[];
  platforms: Platform[];
  events: TimelineEvent[];
  updatedAt: string;
}
```

Сейчас демонстрационные данные находятся в компонентах. Следующий архитектурный шаг - вынести их в `core/data/conflicts.repository.ts`, а затем заменить реализацию репозитория HTTP-клиентом без изменения компонентов.

## Управление состоянием

- Signals используются только для локального UI: поисковая строка, фильтр, мобильное меню и модальное окно.
- Адрес открытого конфликта хранится в Router, а не в локальном состоянии.
- Серверные данные не должны дублироваться в нескольких компонентах; их предоставляет репозиторий.
- Глобальный store не вводится, пока не появится совместно используемое изменяемое состояние.

## Палитра и стили

Палитра определена в `src/styles.scss` в двух слоях:

1. Raw-токены (`--slate-*`, `--blue-*`) описывают конкретные цвета.
2. Семантические токены (`--text-muted`, `--surface-card`, `--status-live`) описывают назначение.

Компоненты используют только семантические токены. Добавлять новые hex-, rgb- или именованные цвета в компонентные SCSS нельзя. Если существующего значения не хватает, сначала добавляется raw-токен, затем семантический токен.

Текстовые уровни:

- `--text-primary` - заголовки и основной текст;
- `--text-secondary` - описания и содержательные подписи;
- `--text-muted` - даты, метаданные и вспомогательные элементы;
- `--text-faint` - только некритичный декоративный текст достаточного размера.

Мелкий текст до `12px` нельзя окрашивать в `--text-faint`: для него используется минимум `--text-muted`.

Базовый визуальный масштаб приложения - `1.25`, заданный глобально для `body`. Макеты и контрольные снимки проверяются при масштабе браузера 100%; дополнительное увеличение браузером считается пользовательской настройкой доступности.

### UI Kit

Переиспользуемые примитивы находятся в `src/styles/_ui-kit.scss`. Базовая кнопка собирается из `.ui-button`, `.ui-button__icon` и `.ui-button__label`; варианты задаются модификаторами `--primary` и `--compact`. Иконка всегда имеет собственный квадратный контейнер, поэтому её baseline не влияет на центрирование текста.

## Компонентные границы следующего этапа

При расширении проекта главная страница делится на:

- `ConflictCardComponent` - карточка и ссылка на материал;
- `ConflictFiltersComponent` - поиск и фильтры;
- `TimelineComponent` - список событий;
- `ParticipantBadgeComponent` - единое представление участника;
- `EditorialNoticeComponent` - методология и редакционные предупреждения.

Деление выполняется при повторном использовании или усложнении блока, а не заранее ради количества файлов.

Карточка события таймлайна может содержать медиа-предпросмотр первоисточника. Для видео показываются площадка, длительность и кнопка воспроизведения; для текстовой публикации - тип записи и ссылка на оригинал. Превью является ссылкой, а не встроенным плеером: это сохраняет скорость страницы и не загружает сторонние трекеры до действия пользователя.

Люди в материале делятся на две группы: `people` - непосредственные стороны конфликта, `commentators` - авторы публичных реакций и комментариев. Обе группы отображаются как раскрываемые списки в боковом блоке «О материале». У комментатора хранится массив `eventIndexes`: при одной реакции строка сразу прокручивает к событию, при нескольких раскрывается вложенный список всех его комментариев. Пункт комментария плавно прокручивает к карточке, не меняя URL, и выделяет её через локальное состояние `activeEventIndex`. Комментатор не становится участником только из-за упоминания ситуации. Список источников отдельно не дублируется: каждый источник привязан к конкретному событию хронологии.

Фильтр `hideCommentary` скрывает события, на которые ссылается хотя бы один `commentator.eventIndexes`, и оставляет основную цепочку конфликта. Переход к скрытому комментарию из боковой навигации сначала автоматически отключает фильтр, затем прокручивает страницу к событию.

## Редакционный слой материала

- Каждое событие показывает тип: основное событие, заявление, комментарий или итог.
- Источник имеет видимый статус: первоисточник, несколько подтверждений или проверено редакцией.
- Кнопка события копирует прямой URL с fragment-id, не меняя текущий адрес страницы.
- Блок позиций сторон отделяет заявления участников от подтверждённых обстоятельств.
- Журнал изменений объясняет, когда и почему редакция обновляла материал.
- Статус конфликта дополнен ожидаемым следующим шагом.
- Форма исправления требует конкретную неточность и ссылку на подтверждение.

## Доступность

- Все интерактивные карточки должны быть ссылками `routerLink`, а не `div` с обработчиком клика.
- Для клавиатурного фокуса используется глобальный `--focus-ring`.
- Состояние не передаётся только цветом: рядом со статусом всегда есть текст.
- Контраст мелких метаданных проверяется отдельно от крупного текста.

## SEO

- Каждый конфликт имеет отдельный URL и уникальные `title`/`description`.
- Перед публикацией требуется Angular SSR или prerender для всех известных slug.
- Нужны `sitemap.xml`, canonical URL и Open Graph-метаданные страницы.
- Удалённые материалы возвращают корректный `404` или `410`, переименованные - постоянный редирект.

## Проверка изменений

Минимальная проверка перед слиянием:

```bash
npm run build
```

Для изменений маршрутизации дополнительно проверяются прямое открытие URL, переход с главной и возврат назад. Для палитры проверяются обычное, hover-, focus- и disabled-состояния на мобильной и настольной ширине.
